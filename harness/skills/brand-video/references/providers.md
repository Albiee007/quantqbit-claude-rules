# Providers: generated voice, word alignment and b-roll

The harness ships no vendor client and stores no key. A project that wants generated media declares its **own commands** in `brand/video/providers.json`, and the main session runs them with `render_video.py generate`, only when the owner has asked for it. Sub-agents can't run `generate`; the guard refuses it.

## providers.json

```json
{
  "schemaVersion": 1,
  "providers": {
    "tts":   { "label": "ElevenLabs via tools/tts.py", "env": ["ELEVENLABS_API_KEY"],
               "command": ["{python}", "tools/tts.py", "--voice-prompt", "{prompt}", "--text", "{text}", "--out", "{out}"],
               "terms": "docs/licences.md#voice" },
    "align": { "label": "whisperX on this machine",
               "command": ["{python}", "tools/align.py", "{audio}", "{text}", "{out}"] },
    "broll": { "label": "an image model via tools/broll.py", "env": ["IMAGE_API_KEY"],
               "command": ["{python}", "tools/broll.py", "{prompt}", "{out}", "{width}", "{height}", "{seconds}"] }
  }
}
```

- `command` runs from the project root, with no shell. Each argument's placeholders are filled in:
  - `tts`: `{text}` (a file with the line), `{out}` (the WAV to write), `{scene}`, `{language}`, `{casting}`, `{prompt}` (the generated voice prompt).
  - `align`: `{audio}` (the take), `{text}`, `{out}` (JSON), `{scene}`, `{language}`.
  - `broll`: `{prompt}` (a file with the scene's `media.prompt`), `{out}`, `{scene}`, `{width}`, `{height}`, `{seconds}`, `{fps}`.
  - `{python}` is the Python running the harness.
- `env` names the environment variables the command needs. They must be set in the environment, never in a project file. Their values are not read into any record, hash or log.
- `terms` says where the provider's licence or terms for generated media are recorded.
- A command must write `{out}` and exit 0 within `timeoutS` (default 900).

## generate

```
python render_video.py generate <id> --what tts|align|broll [--scene <id>] [--force]
```

- **tts:** one take per scene with a `vo` line, written to `brand/video/<id>/media/vo/<scene>.wav`. Takes that exist are kept unless `--force`.
- **align:** for each take, `brand/video/<id>/media/vo/<scene>.words.json`: `{"take": <sha256 of the take>, "words": [{"word", "start", "end"}]}`, seconds into the take. A later render uses it only while the take is the same bytes, and the captions become **word-aligned**: each caption starts at its first word and ends at its last.
- **broll:** for each scene with `media.prompt`, the file named by its `media.image` or `media.video`, under `brand/video/<id>/media/`.

Every generated file is recorded in `brand/video/<id>/media/provenance.json`: the kind, the provider's label, the time, the file's sha256, and the sha256 of the text or prompt it came from.

## Approvals and disclosure

- **Generated bytes are approved like any other.** A generated picture or recording is part of the storyboard approval; a generated take is part of the mix approval. Generating again changes the bytes, so the owner looks or listens again.
- **The provider is not part of any approval.** Changing a provider, its command or a key changes no hash; only what it generates does.
- **Disclosure.** A render lists every generated voice take (`disclosure:ai-voice`) and every scene showing generated media (`disclosure:ai-media:<scene>`) as REVIEW REQUIRED items of kind `suitability`. Platforms ask for synthetic voice and AI-generated imagery to be labelled (YouTube, TikTok, Meta, the App Store). The run manifest lists the generated files under `generated`.
- If the owner replaces a generated file with their own, its bytes no longer match provenance, and it is the owner's own again.

## Rules

- Never generate a real person's voice or likeness, another brand's marks, or footage of features the product doesn't have.
- A generated voice still follows the voice prompt's casting, and the claims guardrails apply to every line.
- Drafts first: `generate`, then `preview`, then the owner approves the storyboard or the mix as usual.
